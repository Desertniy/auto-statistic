## Исходный запрос
> ...помогло бы перекупам автомобилей удобно наблюдать за всеми автомобилями...

Третья фича MVP по карте из [`docs/PRD.md`](../../PRD.md), раздел 12. Источник требований: PRD 5.1 (кроме архива
и фильтров по статусам и архиву), 5.6 (изоляция данных), NFR-SEC-3 (событие отказа в доступе к чужому объекту).

## Проблема и цель
Первая бизнес-сущность — машина. Вместе с ней закладывается правило, которое действует для всех следующих данных:
каждый объект принадлежит владельцу, и чужой объект неотличим от несуществующего. Отдельной фичей изоляцию не делаем:
без данных её нечем проверить. Поэтому правило вводится здесь, на первой сущности. Каждая следующая фича обязана
иметь критерии приёмки по изоляции (FR-ISO-8), а F-011 проверяет изоляцию сквозным регрессионным набором.

**Цель:** перекуп заводит машины, видит и правит их карточки, ищет по списку. Другой пользователь ничего из этого не видит.

**Признак успеха:** два пользователя заводят по машине. Каждый видит только свою, а попытки обратиться к чужой
по идентификатору дают «не найдено».

## Пользовательские сценарии
- Как перекуп, я хочу добавить купленную машину с ценой и датой покупки, чтобы начать по ней учёт.
- Как перекуп, я хочу исправить данные карточки, если ошибся при вводе.
- Как перекуп, я хочу видеть список своих машин и искать по марке, модели, VIN и госномеру.
- Как перекуп, я хочу быть уверен, что мои машины не видит никто другой.

## Объём
**Входит:**
- Создание машины со статусом «Куплена» (этот статус пока единственный), просмотр карточки, редактирование.
- Список своих машин с поиском и сортировкой.
- Владелец объекта, правило «чужое = не найдено», событие аудита при обращении к чужому объекту, автотесты изоляции.

**Не входит (out of scope):** смена статусов, свои статусы, история и фильтр по статусам — F-005; продажа — F-006;
архив — F-007; затраты — F-008. Физического удаления машин нет (PRD Q8).

## Критерии приёмки фичи
- [ ] AC-1: Given пользователь A, When он создаёт машину с обязательными атрибутами, Then машина сохранена со статусом
  «Куплена», видна A по идентификатору и в списке и остаётся после перезапуска.
- [ ] AC-2: Given машина пользователя A, When пользователь B читает или редактирует её по идентификатору, Then ответ
  такой же, как для несуществующего идентификатора, машина не изменена, а в журнале аудита есть событие отказа в доступе.
- [ ] AC-3: Given у A и B есть машины, When каждый запрашивает список или ищет, Then каждый видит только свои.
- [ ] AC-4: Given у A уже есть машина с VIN `XTA21099071234567`, When A создаёт вторую с тем же VIN, Then ошибка
  уникальности. When B создаёт машину с тем же VIN, Then успех.

## Нефункциональные требования
- Список до ~1 000 машин на пользователя отвечает до 1 с (NFR-4).
- «Сегодня» в проверках дат — по московскому времени (NFR-2).

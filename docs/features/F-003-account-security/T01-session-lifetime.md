## Описание
Сессия из F-002/T06 получает ограниченный срок жизни: 30 дней без активности и не больше 90 дней с момента входа
(PRD FR-SES-1, подтверждено). Учётные данные, которые передаются с каждым запросом, краткоживущие (минуты)
и продлеваются в рамках действующей сессии без повторного ввода пароля (FR-SES-2, пожелание). Конкретные сроки
и механизм выбирает architect (QA1).

## Критерии приёмки
- [ ] AC-1: Given сессия, которой пользовались последний раз 29 дней назад, When ею пользуются, Then она работает,
  и отсчёт неактивности начинается заново.
- [ ] AC-2: Given сессия без активности 30 дней и более, When ею пользуются или пытаются продлить, Then ответ
  «не аутентифицирован», нужен повторный вход.
- [ ] AC-3: Given сессия, которой пользовались ежедневно, When с момента входа прошло 90 дней, Then она завершена,
  нужен повторный вход. Активность продлевает срок неактивности, но не продлевает сессию дальше 90 дней.
- [ ] AC-4: Given истёк срок краткоживущих учётных данных, но сессия действует, When клиент продлевает их по правилам
  механизма, Then он получает новые учётные данные без ввода пароля, а истёкшие больше не принимаются.
- [ ] AC-5: Given сессия завершена выходом (F-002/T06), When клиент пытается её продлить, Then продление отклонено.
- [ ] AC-6: Given сроки (30 и 90 дней, срок краткоживущих данных), When просмотрена конфигурация, Then сроки задаются
  параметрами, а значения по умолчанию соответствуют PRD.
- [ ] AC-7: Given сессия завершилась по сроку, When просмотрен журнал аудита, Then есть событие истечения сессии
  (Допущение: пишется в момент обнаружения истечения).

## Описание
Пользователь, забывший пароль, запрашивает ссылку восстановления на email и устанавливает новый пароль
(PRD FR-PWD-4, FR-PWD-5). Ответ на запрос не раскрывает, есть ли аккаунт. Ссылка одноразовая и живёт 1 час.
После сброса завершаются все сессии.

## Критерии приёмки
- [ ] AC-1: Given существующий аккаунт, When запрошено восстановление для его email (в любом регистре), Then ответ
  «если аккаунт существует, мы отправили письмо», а в заглушке почты есть письмо со ссылкой.
- [ ] AC-2: Given email без аккаунта, When запрошено восстановление, Then ответ такой же, как в AC-1, письмо не отправлено.
- [ ] AC-3: Given действующая ссылка и корректный новый пароль, When пароль установлен, Then вход с новым паролем
  успешен, со старым — «неверный email или пароль». Все сессии пользователя, открытые до сброса, недействительны.
  На email пришло уведомление о смене пароля.
- [ ] AC-4: Given ссылка использована, When её применяют повторно, Then ошибка «ссылка недействительна».
- [ ] AC-5: Given ссылке больше 1 часа, When её применяют, Then ошибка «срок действия ссылки истёк», пароль не изменён.
  В тестах время управляемо.
- [ ] AC-6: Given запрошены две ссылки подряд, When применяется первая, Then она недействительна, а вторая работает.
- [ ] AC-7: Given новый пароль нарушает правила FR-PWD-1/2, When его устанавливают по ссылке, Then ошибка с причиной,
  ссылка остаётся действительной до истечения срока (Допущение).
- [ ] AC-8: Given аккаунт с неподтверждённым email, When пароль установлен по ссылке восстановления, Then email
  считается подтверждённым, и вход разрешён (Допущение PRD A14).
- [ ] AC-9: Given запрос восстановления и установка пароля, When просмотрены журнал аудита, хранилище и логи, Then
  оба события записаны, а токен ссылки в открытом виде не хранится и не логируется.

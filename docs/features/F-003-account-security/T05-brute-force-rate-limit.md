## Описание
Защита от подбора паролей и злоупотреблений (PRD FR-SEC-1..3). Временная блокировка входа по аккаунту плюс
ограничение частоты для входа, регистрации, повторной отправки письма подтверждения, восстановления и смены пароля —
по аккаунту (email) и по IP. Числа — допущение PRD A15. Пороги частоты по IP выбирает architect, они задаются
конфигурацией.

## Критерии приёмки
- [ ] AC-1: Given 5 неудачных попыток входа в один аккаунт за 15 минут, When шестая попытка, даже с верным паролем,
  Then ответ «слишком много попыток, повторите позже» с временем ожидания. Вход в другие аккаунты с того же IP
  ограничивается только лимитом по IP (AC-5).
- [ ] AC-2: Given блокировка на 15 минут истекла, When вход с верным паролем, Then вход успешен, счётчик неудач сброшен.
  Given после блокировки снова 5 неудач, When следующая блокировка, Then она длиннее предыдущей. Постоянной блокировки нет.
- [ ] AC-3: Given 4 неудачные попытки и затем успешный вход, When снова 4 неудачи, Then блокировки нет: успешный вход
  сбросил счётчик.
- [ ] AC-4: Given несуществующий email, When по нему 5 неудачных попыток, Then ответ такой же, как для существующего
  аккаунта, включая блокировку. По ответам нельзя понять, есть ли аккаунт (FR-SEC-3).
- [ ] AC-5: Given с одного IP превышен порог запросов к входу, регистрации, повторной отправке письма, восстановлению
  или смене пароля, When следующий запрос, Then ответ «слишком много попыток» с временем ожидания. Запросы с других IP
  не затронуты.
- [ ] AC-6: Given для одного email превышен порог запросов повторной отправки или восстановления, When следующий
  запрос, Then письмо не отправляется, а ответ не раскрывает существование аккаунта.
- [ ] AC-7: Given два экземпляра приложения, When неудачные попытки идут попеременно через оба, Then счётчик общий,
  и блокировка срабатывает после 5 попыток суммарно.
- [ ] AC-8: Given блокировка и превышение частоты, When просмотрен журнал аудита, Then события записаны (аккаунт
  или email, IP, тип ограничения).

## Описание
Вошедший пользователь меняет пароль, указывая текущий. Остальные сессии завершаются, текущая остаётся, на email
приходит уведомление (PRD FR-PWD-3). К новому паролю применяются те же правила, что при регистрации (FR-PWD-1, FR-PWD-2).

## Критерии приёмки
- [ ] AC-1: Given пользователь вошёл на двух устройствах, When на первом меняет пароль с верным текущим и корректным
  новым, Then смена успешна, первая сессия продолжает работать, вторая сразу недействительна.
- [ ] AC-2: Given пароль сменён, When вход со старым паролем, Then «неверный email или пароль». Вход с новым — успешен.
- [ ] AC-3: Given пароль сменён, When просмотрена заглушка почты, Then на email пользователя пришло уведомление
  о смене пароля с рекомендацией восстановить пароль, если менял не он. Самого пароля в письме нет.
- [ ] AC-4: Given неверный текущий пароль, When запрос смены, Then ошибка «текущий пароль неверен», пароль не изменён,
  другие сессии не затронуты.
- [ ] AC-5: Given новый пароль нарушает правила (короче 12, длиннее 128, из списка скомпрометированных, совпадает
  с email), When запрос смены, Then ошибка как при регистрации, пароль не изменён.
- [ ] AC-6: Given новый пароль совпадает с текущим, When запрос смены, Then ошибка «новый пароль должен отличаться
  от текущего» (Допущение).
- [ ] AC-7: Given успешная и неуспешная смена, When просмотрен журнал аудита, Then обе записаны с результатом, без паролей.

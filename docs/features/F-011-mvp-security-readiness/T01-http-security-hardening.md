## Описание
Единые настройки HTTP-безопасности API (PRD NFR-SEC-2, NFR-SEC-5, NFR-5). Веб-интерфейс — отдельный проект на своём
домене, домен пока неизвестен (O1, отложено), поэтому список разрешённых источников CORS задаётся конфигурацией.
HTTPS вне локальной разработки обязателен. Где завершается TLS (приложение или прокси), решает architect.

## Критерии приёмки
- [ ] AC-1: Given эксплуатационный режим, When ответ API, Then есть заголовок HSTS, а также заголовки, запрещающие
  угадывание типа содержимого и встраивание во фреймы. Набор заголовков — по рекомендации architect на основе ASVS.
- [ ] AC-2: Given эксплуатационный режим и запрос по HTTP без TLS, When запрос, Then данные по HTTP не отдаются
  (перенаправление или отказ, выбор за architect).
- [ ] AC-3: Given в конфигурации разрешён источник `https://app.example.test`, When запрос из браузера с этого
  источника, Then CORS разрешён. Given запрос с другого источника, Then CORS не разрешён. Шаблон «любой источник»
  в эксплуатационном режиме запрещён: при такой настройке приложение не стартует.
- [ ] AC-4: Given не настроен ни один источник CORS в эксплуатационном режиме, When старт, Then понятная ошибка
  конфигурации (Допущение).
- [ ] AC-5: Given внутренняя ошибка на сервере, When ответ, Then единый формат ошибки без стек-трейса, имён классов,
  SQL и версий библиотек. Подробности — только в техническом логе.
- [ ] AC-6: Given выбранный механизм сессий использует cookie, When просмотрены cookie, Then у них есть `Secure`,
  `HttpOnly`, `SameSite`, и защита от CSRF включена. Если cookie не используются, это явно отмечено в результате задачи.
- [ ] AC-7: Given локальная разработка, When приложение запускается, Then оно работает по HTTP без дополнительной
  настройки, как раньше.

# ADR-0010: Пароли — Argon2id через `DelegatingPasswordEncoder`, локальный список распространённых паролей
- Статус: Accepted
- Дата: 2026-11-08
- Фича: F-002

## Контекст
PRD QA2, FR-PWD-1/2/6: пароль 12–128 символов, любые символы (пробелы, Unicode); отклонять распространённые
и скомпрометированные пароли и пароль, равный email; хранить результатом медленной адаптивной функции с солью
по OWASP Password Storage Cheat Sheet, с возможностью усилить параметры позже без сброса паролей.
Ограничения: bcrypt обрабатывает не более 72 байт (Spring Security 7 отклоняет более длинные пароли), а 128 символов
кириллицы — до 256 байт UTF-8 (до 512 для 4-байтовых символов). Обращение к внешним сервисам с данными пользователей —
только с обработкой в РФ (FR-PD-1).

## Решение
1. **Алгоритм — Argon2id** с параметрами OWASP (минимальная рекомендуемая конфигурация): память 19 MiB (19456 KiB),
   2 итерации, параллелизм 1, соль 16 байт, хеш 32 байта. Реализация — `org.springframework.security.crypto.argon2.Argon2PasswordEncoder`
   (`spring-security-crypto`, без версии — BOM) + `org.bouncycastle:bcprov-jdk18on` (в BOM Boot нет; версия
   `bouncycastle = "1.86"` в каталоге).
2. **Формат хранения** — через `DelegatingPasswordEncoder` с идентификатором `argon2id-v1`:
   `{argon2id-v1}$argon2id$v=19$m=19456,t=2,p=1$<соль>$<хеш>`. Параметры закодированы в самом хеше.
   Усиление позже: новый id (`argon2id-v2`) становится кодировщиком по умолчанию, старый остаётся для проверки;
   `upgradeEncoding()` даёт признак для перехеширования при следующем успешном входе (реализуется вместе с изменением
   параметров, не в F-002).
3. **Порт в домене** — `PasswordHasher` (`hash(ValidPassword): PasswordHash`, `matches(RawPassword, PasswordHash): Boolean`,
   `matchesDummy(RawPassword): Unit` — проверка против «пустого» хеша из п. 4, результат не используется), реализация —
   `account.infrastructure.Argon2PasswordHasher`. Spring Security в домен не попадает.
4. **Выравнивание времени входа:** при неизвестном email выполняется `matches` против заранее вычисленного при старте
   «пустого» хеша (FR-AUTH-6). При регистрации на занятый email пароль тоже хешируется (результат отбрасывается).
5. **Без нормализации пароля:** пароль хешируется в том виде, как введён (UTF-8, без trim и Unicode-нормализации);
   длина считается в Unicode code points (`String.codePointCount`).
6. **Список распространённых паролей — локальный ресурс** `src/main/resources/security/common-passwords.txt`:
   из репозитория `danielmiessler/SecLists` (лицензия MIT), каталог `Passwords/Common-Credentials/`, топ-100 000;
   в файл попадают только строки длиной 12–128 code points (короче отклоняются правилом длины), плюс обязательные
   записи из критериев приёмки (`password1234`). Источник, коммит SecLists и способ фильтрации записываются в первых
   строках-комментариях файла (`#`). Загружается при старте в `Set<String>` (сравнение без учёта регистра,
   `lowercase(Locale.ROOT)`).

## Последствия
- (+) Соответствует OWASP; нет ограничения 72 байт; параметры можно усилить без сброса паролей.
- (+) Проверка утечек — офлайн, без передачи данных за рубеж и без сетевой зависимости при регистрации.
- (−) ~19 MiB памяти и десятки мс CPU на вычисление: массовые запросы входа/регистрации — вектор DoS до
  ограничения частоты в F-003/T05.
- (−) Локальный список устаревает и не покрывает свежие утечки; обновление — заменой ресурса.
- (−) Новая зависимость BouncyCastle — версия ведётся вручную (следить за CVE, F-011/T03).

## Рассмотренные альтернативы
- **bcrypt (cost 12)** — ограничение 72 байта противоречит 128 символам Unicode; пред-хеширование SHA-256 усложняет
  и даёт известные подводные камни.
- **scrypt / PBKDF2** — допустимы по OWASP, но Argon2id — первая рекомендация.
- **HIBP Pwned Passwords API (k-anonymity)** — актуальнее, но внешний зарубежный сервис и сетевая зависимость в
  критическом пути регистрации.

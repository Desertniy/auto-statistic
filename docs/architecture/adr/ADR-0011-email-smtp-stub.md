# ADR-0011: Письма — SMTP через `spring-boot-starter-mail`, режимы `stub`/`smtp`, синхронная отправка после коммита
- Статус: Accepted
- Дата: 2026-11-08
- Фича: F-002

## Контекст
PRD QA4, NFR-SEC-7, FR-PD-1: письма (подтверждение email, уведомления, позже — восстановление пароля) уходят через
почтовый сервис с обработкой данных в РФ; провайдер, домен и адрес отправителя не выбраны (PRD O1, O2). В разработке
и тестах письма перехватываются заглушкой; в логах — только факт отправки, без содержимого и ссылок с токенами.
Сбой почты не должен ронять пользовательскую операцию (F-002/T03 AC-4). Ссылки ведут на отдельный веб-интерфейс,
его базовый адрес задаётся конфигурацией. BOM Boot 4.1.2 управляет `spring-boot-starter-mail` и Angus Mail 2.0.5.

## Решение
1. **Транспорт — SMTP** (`spring-boot-starter-mail`, `JavaMailSender`). SMTP поддерживают российские провайдеры
   (почтовые сервисы и транзакционные рассыльщики), поэтому выбор провайдера (O2) — смена параметров окружения
   (`SPRING_MAIL_HOST`, `SPRING_MAIL_PORT`, `SPRING_MAIL_USERNAME`, `SPRING_MAIL_PASSWORD` — стандартная relaxed binding Boot для `spring.mail.*`), без кода. HTTP-API конкретного провайдера не используется.
2. **Порт** `com.autostatistic.mail.application.EmailSender`:
   `fun send(message: EmailMessage): Either<EmailDeliveryFailed, Unit>`; `EmailMessage(to: EmailAddress, kind: EmailKind,
   subject: String, body: String)` — текст (`text/plain; charset=UTF-8`), на русском. `EmailKind` — value class с кодом типа
   письма для логов (`"email-confirmation"` и т.п.), задаётся модулем-отправителем.
3. **Режим** `app.mail.mode: stub | smtp`. В основном `application.yaml` — `smtp` (безопасное значение для эксплуатации);
   профили `local` и `test` — `stub`.
   - `StubEmailSender` (`mode=stub`): хранит письма в памяти (потокобезопасно), отдаёт их через интерфейс
     `CapturedEmails` (`lastFor(address)`, `allFor(address)`); пишет в лог INFO `Email captured by stub: kind=…, to=…` —
     без темы, тела и ссылок. Изменяемое состояние в бине допустимо только здесь (заглушка) — с комментарием-причиной.
   - `SmtpEmailSender` (`mode=smtp`): отправляет через `JavaMailSender`; `MailException` → лог ERROR
     `Email delivery failed: kind=…, to=…, error=<класс исключения>` (без тела и без `message` исключения, где может
     оказаться содержимое) → `Left(EmailDeliveryFailed)`.
4. **Синхронная отправка после коммита** транзакции use case (ADR-0008, п. 3). `Left` от отправителя логируется
   вызывающим use case и не меняет HTTP-ответ: пользователь может запросить письмо повторно (T05). Таймауты SMTP —
   5 с на соединение, чтение и запись (`spring.mail.properties.mail.smtp.{connectiontimeout,timeout,writetimeout}`).
5. **Проверка конфигурации при старте:** `app.web.base-url` (абсолютный `http(s)` URL) обязателен во всех режимах
   (в профилях `local`/`test` задан); при `mode=smtp` дополнительно обязательны `app.mail.from-address` (валидный email)
   и `spring.mail.host`; иначе старт падает с понятным сообщением
   (проверки в `init` у `@ConfigurationProperties`-классов и в конфигурации `SmtpEmailSender`). Отправка с пустыми
   параметрами невозможна.
6. **Ссылки** строятся компонентом `WebLinks` от `app.web.base-url` (`UriComponentsBuilder`, путь + query, корректное
   кодирование); шаблоны писем — функции Kotlin в модуле-отправителе, без шаблонизатора.
7. **Health:** `management.health.mail.enabled: false` — недоступность почты не делает приложение `DOWN`.

## Последствия
- (+) Провайдер меняется конфигурацией; заглушка детерминирована и читается тестами напрямую.
- (+) Нет очереди/outbox и фоновых потоков — минимум движущихся частей.
- (−) Медленный SMTP увеличивает время ответа (до таймаута 5 с); сбой отправки не повторяется автоматически —
  письмо теряется, пользователь запрашивает повторно (для письма «попытка регистрации на ваш email» повтора нет).
- (−) Разное время ответа в ветках «письмо отправлено / не отправлено» (повторная отправка, занятый email) частично
  раскрывает существование аккаунта по таймингу; принимается до ограничения частоты (F-003/T05). Пересмотреть
  (асинхронная отправка / outbox), если появятся требования к доставке или таймингу.

## Рассмотренные альтернативы
- **Transactional outbox + фоновая отправка** — надёжная доставка и ровное время ответа, но таблица, планировщик,
  повторы и блокировки между экземплярами; избыточно для MVP.
- **`@Async` / `@TransactionalEventListener(AFTER_COMMIT)` + executor** — ровнее время ответа, но письма теряются при
  остановке экземпляра и сложнее тестировать; можно перейти позже без смены порта `EmailSender`.
- **HTTP-API провайдера** — привязка к провайдеру, который ещё не выбран (O2).
- **GreenMail/Mailpit в тестах** — проверка реального SMTP; для критериев достаточно in-memory заглушки. Mailpit
  можно использовать локально в режиме `smtp` (необязательно, описывается в README).

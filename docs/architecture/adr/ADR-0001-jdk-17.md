# ADR-0001: Платформа — JDK 17 (LTS) через Gradle toolchain
- Статус: Accepted
- Дата: 2026-10-23
- Фича: F-001

## Контекст
В `overview.md` целевым стеком была указана JVM 21. В IDE разработчика настроен JDK 17 (`liberica-17`,
также установлен `corretto-17`), JDK 21 не установлен. Пользователь явно выбрал JDK 17 (ответ на Q5 в F-001).
Выбор версии JDK влияет на всю систему: доступные API, версии библиотек, требования к окружению запуска,
а смена версии позже затрагивает сборку, CI и рантайм.

Ограничения выбранного стека относительно JDK 17:
- Spring Boot 4.1 — минимум Java 17 (совместим до 27).
- Gradle 9.x — для запуска самого Gradle нужен JVM 17+.
- Kotlin 2.3 — генерирует байткод для JVM 17 без ограничений.

## Решение
- Целевая платформа — **Java 17 (LTS)**, байткод `jvmTarget = 17`.
- Версия фиксируется в сборке через **Gradle toolchain**: `kotlin { jvmToolchain(17) }` в `build.gradle.kts`
  (задаёт одновременно Java toolchain и `jvmTarget` Kotlin). Сборка не зависит от того, каким JDK запущен Gradle,
  если на машине обнаруживается JDK 17 (Gradle автоматически находит JDK из `JAVA_HOME`, `PATH`,
  реестра Windows, `~/.jdks` IntelliJ, SDKMAN и т.п.).
- Автоскачивание JDK (плагин `org.gradle.toolchains.foojay-resolver-convention`) **не подключаем**: JDK 17 —
  явное требование к окружению разработчика (AC-1 T01: «установлен JDK требуемой версии»).
- Дистрибутив JDK не фиксируется (Liberica, Corretto, Temurin — любой JDK 17).

## Последствия
- Плюсы: совпадает с окружением разработчика; поддерживается всеми выбранными библиотеками; toolchain
  делает версию явной и воспроизводимой; переход на 21/25 — смена одного числа + новый ADR.
- Минусы: недоступны виртуальные потоки (Loom, JDK 21+) и новые API (sequenced collections, pattern matching
  для `switch` в Java — для Kotlin-кода несущественно). Для Web MVC это означает классическую модель
  «поток на запрос» (пул Tomcat) — для текущих нагрузок достаточно.
- Если на машине нет JDK 17, сборка падает с ошибкой Gradle «No matching toolchains found» — сообщение понятное,
  решение — установить JDK 17.
- JDK 17 поддерживается вендорами (Liberica/Corretto/Temurin) как минимум до 2027–2029 гг.; пересмотреть решение
  при планировании продакшен-развёртывания.

## Рассмотренные альтернативы
- **JDK 21 (прежний целевой стек):** виртуальные потоки, новее LTS. Отклонено решением пользователя: требует
  установки нового JDK, выигрыш для текущего объёма отсутствует.
- **JDK 25 (новейший LTS):** отклонено по той же причине; часть инструментов ещё тестируется на нём.
- **Без toolchain (сборка тем JDK, которым запущен Gradle):** отклонено — версия неявная, сборка JDK 21+
  тихо выдаст байткод другой версии.
- **Toolchain + foojay auto-provisioning:** отклонено (YAGNI) — требует сети и добавляет плагин; вернуться к нему
  при настройке CI (вне F-001).
